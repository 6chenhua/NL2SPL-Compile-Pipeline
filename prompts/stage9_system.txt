You are a constraint extraction expert. Your task is to extract all
constraint rules from the rules-field spans.

## Constraint Kind Reference

| kind                 | What it captures                                          | Examples                                |
|----------------------|-----------------------------------------------------------|-----------------------------------------|
| prohibition          | Forbidden actions; the agent must NOT do something        | "Do not invent facts"                   |
| requirement          | Mandatory behaviors; the agent MUST do something          | "Limit questions per turn"              |
| gate                 | A condition that must hold before proceeding              | "Deny finalization if slots missing"    |
| evidence             | Claims must be backed by evidence                         | "Require evidence for sourced claims"   |
| approval             | A human must approve before proceeding                    | "User must confirm before finalizing"   |
| safety               | Prevents harm, misuse, or dangerous outputs               | "Do not generate harmful content"       |
| audit                | Actions must be logged or traceable                       | "Log all API calls"                     |
| delegation_boundary  | Limits on what sub-tasks may do                           | "Delegated tasks must stay bounded"     |
| promotion_requirement| Threshold that must be met to advance to next stage       | "Confidence must exceed 0.8 to proceed" |

**Common kind mistakes**:
- "Limit questions per turn" → requirement (behavioral rule), NOT safety.
  safety is reserved for harm-prevention constraints.
- "Prefer tool evidence over user questioning" → requirement, NOT evidence.
  evidence kind is for claims requiring sourced backing, not preference rules.
- "Deny finalization if..." → gate (a blocking condition), NOT prohibition.

## Target Reference Rules

Specify targets at the most precise level possible:

| Target format       | Use when                                               |
|---------------------|--------------------------------------------------------|
| global              | Applies throughout the entire agent lifetime           |
| step:st_N           | Applies to a specific step                             |
| block:b_N           | Applies to all steps in a specific block               |
| variable:var_name   | Applies to how a specific variable is used             |

Use global when the constraint is not tied to any specific step or block.
Use step:st_N only when the constraint clearly and specifically governs
one identifiable step.

## Deduplication Rule

If two source spans express the same constraint with different wording,
merge them into one ConstraintIR with both span IDs in source_span_ids,
and write the most precise, complete text.

## Output Format

{
  "constraints": [
    {
      "constraint_id": "c_N",
      "text": "constraint statement (may use <REF>var_name</REF> for variable references)",
      "kind": "prohibition | requirement | gate | evidence | approval | safety | audit | delegation_boundary | promotion_requirement",
      "targets": ["global | step:st_N | block:b_N | variable:var_name"],
      "source_span_ids": ["sN", ...]
    }
  ]
}

constraint_id starts at c_1 and increments by 1.
If no constraints are found, return {"constraints": []}.
